# Прогон evals

Провайдер: `$ARGUMENTS`. Если пусто — `fake`.
`real` запускай, только если пользователь явно попросил и в окружении есть `ANTHROPIC_API_KEY` (проверь через `uv run python -c "import os; print(bool(os.getenv('ANTHROPIC_API_KEY')))"`, сам ключ никогда не печатай).

## Шаги

1. Сохрани прошлый отчёт для сравнения: `git show HEAD:evals/report.md` (если его нет — это первый прогон).
2. Запусти: `uv run python -m evals.run --provider <provider> --out evals/report.md`.
3. Сравни с прошлым отчётом по каждой метрике из SPEC §9 и выведи короткую таблицу:

   | Метрика | Было | Стало | Порог | Статус |

4. Для каждого упавшего кейса: id кейса, вход (сокращённо), что ожидалось, что получили, вероятная причина (промпт / кандидаты / guardrail / БЗ).

## Правила

- Жёсткая метрика ниже 100% — **стоп**: чини причину до коммита и до перехода к следующему этапу.
- Не меняй ожидания в `evals/cases.yaml`, чтобы «позеленело». Если кейс действительно неверен — объясни почему и спроси подтверждения.
- В шапке `evals/report.md` должны быть: дата, провайдер, модель, `PROMPT_VERSION`, хэш коммита, число кейсов.
- Если провайдер `real` — добавь в отчёт суммарные токены, среднюю задержку и оценку стоимости прогона.
