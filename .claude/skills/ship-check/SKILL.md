# Проверка перед сдачей

Пройди все пункты по порядку. В конце выведи чек-лист со статусами ✅/❌ и список того, что исправил.

## 1. Качество кода
- `make check` — зелёный. Покрытие `app/core`, `app/kb`, `app/upsell` ≥ 85%.
- Нет `TODO`/`FIXME`/`print(` в `app/` (кроме CLI): `git grep -nE "TODO|FIXME|print\(" -- app/`.

## 2. Чистый запуск глазами проверяющего
- Склонируй репозиторий во временную папку и пройди быстрый старт **строго по README**, без ключа: `cp .env.example .env && make demo`.
- `curl` из README возвращает валидный ответ с двумя блоками.
- Всё, что пришлось делать сверх README, — это баг README. Исправь.

## 3. Секреты и данные
- `git grep -nE "sk-ant-|api[_-]?key\s*=\s*['\"][^'\"]+" -- . ':!*.example'` — пусто.
- `.env` в `.gitignore`; `.env.example` содержит все переменные с комментариями.
- В логах и фикстурах нет реальных телефонов/email.

## 4. Evals
- `evals/report.md` — свежий (после последнего изменения промпта/БЗ), есть прогон на реальной модели, жёсткие метрики 100%.

## 5. Документация
- README соответствует структуре из SPEC §11, все ссылки живые, есть GIF/скриншот.
- `docs/ARCHITECTURE.md`: mermaid-диаграмма и ADR (минимум: retrieval без векторной БД, гибридная допродажа, один LLM-вызов со структурным выводом, асинхронный вебхук, fake-провайдер).
- `docs/AI_WORKFLOW.md`: как использовался Claude Code (CLAUDE.md, навыки, plan mode, evals, ревью-агент), что проверялось руками, где ИИ ошибался и как это ловилось.

## 6. Ревью
- Запусти агента `tech-lead-reviewer`. Всё из раздела «Критично» — исправить; «Желательно» — исправить, если < 30 минут, иначе в «Что сделал бы дальше».

## 7. История
- `git log --oneline` читается как история работы: осмысленные Conventional Commits, без «fix», «wip», «asdf».
