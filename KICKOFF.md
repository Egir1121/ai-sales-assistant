# KICKOFF — как вести проект в Claude Code

Этот файл для тебя, не для Claude. В репозиторий его можно не коммитить.

## 0. Подготовка (5 минут)

```bash
mkdir ai-sales-assistant && cd ai-sales-assistant && git init
# распакуй сюда архив: CLAUDE.md, docs/, .claude/
# если работодатель дал свою БЗ — положи её в data/kb/source/
git add . && git commit -m "chore: project brief and Claude Code setup"
claude
```

Проверь, что всё подхватилось: набери `/` — в списке должны быть `run-evals`, `prompt-change`, `kb-edit`, `amocrm-integration`, `ship-check`.

## 1. План (plan mode: Shift+Tab, пока не появится plan mode)

> Прочитай CLAUDE.md и docs/SPEC.md. Сначала задай мне до 5 вопросов, если в постановке есть противоречия или развилки, которые сильно меняют архитектуру. Затем составь план по этапам M0–M6: для каждого — файлы, ключевые классы/протоколы, тесты на критерии приёмки, риски. Отдельно предложи содержание ADR-001…ADR-005 для docs/ARCHITECTURE.md. ultrathink

Прочитай план внимательно и поправь до того, как соглашаться. Это самая дешёвая точка для изменений.

## 2. Этапы (по одному, не всё сразу)

> Реализуй M0 по SPEC. Сначала тесты на критерий приёмки, потом код. В конце — make check и коммит.

Повтори для M1, M2, M3. После M2 и после каждой правки промпта:

> /run-evals

После M3 открой http://localhost:8000 и сам прогони сценарии S1, S4, S7 руками. Сделай скриншот — пригодится для README.

> Реализуй M4. Потом /run-evals real (ключ у меня в .env).

> Реализуй M5 по SPEC §8 и навыку amocrm-integration.

## 3. Ревью посередине (после M3)

Чини «Критично» сразу — дальше исправлять дороже.
